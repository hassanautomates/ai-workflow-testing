# CLAUDE.md — ai-workflow-testing

Read `SPEC.md` first. It defines what this repo is. This file defines how to work in it.

## Ground rules
- **Original code only.** This is a public demo written from scratch. Never reproduce code, file names, schemas, block names beyond those in SPEC.md, or data from any employer or private repo, even if asked or if similar code is visible elsewhere on this machine.
- **No invented results.** Any number in the README (runs, failures, bugs caught) must come from `reports/prove.md`, generated by `npm run prove`. If a result isn't produced yet, leave a TODO; don't estimate.
- **No secrets, no external services.** The suite must run offline apart from `npm ci` and the Playwright browser download.
- **Work milestone by milestone** (SPEC.md § Milestones). Stop at the end of each milestone, summarise what changed and what's next, and wait for the go-ahead. Don't start the next milestone unprompted.
- **Small commits with clear messages.** The commit history is part of the portfolio. Do not commit or push unless asked; propose the commit message instead.
- In commit messages and PR descriptions, never add Co-Authored-By lines or any signature or attribution to Claude.

## Code standards
- TypeScript `strict: true`. No `any` unless commented with a reason.
- ESLint with zero warnings; Prettier formatting. Run lint + typecheck before declaring a step done.
- Keep the app and the harness separate: the harness must never import engine code. The mirror is an independent re-implementation, which is the whole point.
- Prefer clear names over clever code. Comment the *why* on taint rules and observed routing.

## Testing rules
- `assertExact` on a tainted value must throw a harness error. Keep a unit test proving it.
- No fixed sleeps in e2e tests. Wait on visible state or explicit app signals.
- No test-level retries. If something is flaky, fix the cause.
- Generated tests: one per published workflow from `GET /api/workflows`. An empty list or API error fails the run.

## Commands (keep these working)
- `npm run dev`: start the app
- `npm test`: unit + e2e
- `npm run lint`, `npm run typecheck`
- `npm run prove`: variance runs plus bug-injection runs, writes `reports/prove.md`

## When unsure
Ask instead of guessing, especially about scope, naming or anything that would end up in the README.
